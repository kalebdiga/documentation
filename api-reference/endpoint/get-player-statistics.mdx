---
title: "Get schedule player statistics"
description: "All player stat rows for one schedule (no pagination). Each row includes nested `player`, `teamId` / `teamName`, and category metric fields as returned on the wire. Omit categories to fetch all five; unrequested keys are `[]`."
openapi: "/openapi.json GET /v1/blitz-api/schedules/{scheduleId}/player-statistics"
---

## Scope

Stats are limited to the **single schedule** in the path. There is no season / multi-game rollup and **no pagination** — each requested category returns its full list.

Each row includes category metrics plus `teamId`, `teamName`, and a nested `player` object (`_id`, `name`, `jerseyNumber`, and optional `position` / `profilePicture` / `userId`).

When both sides have recorded plays (home `teamOneId` and a linked `teamTwoId`), rows from **both teams** are included. The schedule’s home team (`teamOneId`) must belong to the API key organization.

## Envelope

Always:

```json
{
  "data": {
    "meta": {
      "teamOneScore": 27,
      "teamTwoScore": 14,
      "scoreBreakdown": {
        "format": "quarters",
        "teamOne": { "periods": [7, 0, 13, 7], "final": 27 },
        "teamTwo": { "periods": [0, 7, 0, 7], "final": 14 }
      }
    },
    "quarterbackStat": [],
    "offensiveStat": [],
    "defensiveStat": [],
    "puntStat": [],
    "returnStat": []
  }
}
```

| Scenario | Behavior |
| --- | --- |
| Omit `categories` | All five keys populated (or `[]` if no rows for that category) |
| `categories=quarterbackStat&categories=offensiveStat` | Only those arrays may have rows; other keys are `[]` |
| Special teams only | `categories=puntStat&categories=returnStat` — no `specialTeams` key |
| `teamId=<home\|away>` | Same five keys; rows limited to that schedule side |
| No plays / empty ST | Arrays stay `[]` (common for `puntStat` / `returnStat`) |

## Meta (scores + period breakdown)

`data.meta` is always present (same shape whether or not you filter `categories` / `teamId`):

| Field | Description |
| --- | --- |
| `teamOneScore` / `teamTwoScore` | Authoritative finals from the schedule |
| `scoreBreakdown` | Same object as [Get schedule](/api-reference/endpoint/get-schedule) — `format` + per-team `periods` + `final` |

Use `meta.scoreBreakdown.periods` for quarter/half columns. Do **not** invent a period split from the final alone (e.g. `0-0-0-0` with a total of 27). Treat `meta.teamOneScore` / `meta.teamTwoScore` and `scoreBreakdown.*.final` as the game total.

## Categories

| Wire key | What's included |
| --- | --- |
| `quarterbackStat` | Pass, QB rush, sacks taken, extra points |
| `offensiveStat` | Receptions, rushes, extra points |
| `defensiveStat` | Flag pulls, sacks, interceptions, pressures; interception-return touchdowns |
| `puntStat` | Punting |
| `returnStat` | Punt returns |

There is **no** `specialTeams` array. Interception-return touchdowns are `defensiveStat.interceptionReturnTouchDown`, not `returnStat`.

## Shared row fields

Every non-empty row includes:

| Field | Description |
| --- | --- |
| `_id` | Player id |
| `teamId` | Schedule side team id |
| `teamName` | Team display name |
| `player` | Nested player: `_id`, `name`, `jerseyNumber`, optional `position`, `profilePicture`, `userId` |

Do **not** expect flat `playerName` / `jerseyNumber` on the row root. Metric names match the wire (e.g. `totalPassAttempts`, `flagPulls`), not alternate shorthand.

### Nested `player`

```json
{
  "_id": "694d970270d57829dae62a22",
  "name": "avery collins",
  "jerseyNumber": 4,
  "position": ["quarterBack", "wideReceiver"],
  "profilePicture": null,
  "userId": "69175b0a22df2a74c331bad1"
}
```

`jerseyNumber` may be a string or number; `position`, `profilePicture`, and `userId` are omitted or null when unset.

## Metric fields by category

### `quarterbackStat`

`qbLongestRush`, `totalPassAttempts`, `totalCompletions`, `totalPassingTouchdown`, `totalQuarterBackRushTouchdown`, `totalQuarterBackGames`, `totalInterceptionThrown`, `totalIncompletePasses`, `totalQuarterBackPoints`, `longestPass`, `totalPassingYards`, `totalQuarterBackRushYards`, `totalQuarterBackRuns`, `totalSacksTaken`, `totalSackYardage`, `extraPoint1`–`extraPoint3`, `attemptedExtraPoint1`–`attemptedExtraPoint3`, `totalQuarterBackYards`, `completionPercentage`, `averageTotalPassingYardsPerGame`

### `offensiveStat`

`points`, `targets`, `receptions`, `touchdownCatches`, `touchdownRun`, `rushingLong`, `receivingLong`, `receivingYards`, `rushingYards`, `receptionPercentage`, `touchdownRunPerGame`, `receivingYardsPerGame`, `rushYardPerGame`, `totalOffensiveYards`, `runs`, `extraPoint1`–`extraPoint3`, `attemptedExtraPoint1`–`attemptedExtraPoint3`, `games`

### `defensiveStat`

`qbPressures`, `interceptions`, `deflections`, `sacks`, `flagPulls`, `flagPullForLoss`, `interceptionYards`, `sackYardsForced`, `interceptionReturnTouchDown`, `defensiveExtraPointsMade`, `defensiveTryAttempts`, `defensivePoints`, `safety`, `games`

### `puntStat`

`numberOfGames`, `totalNumberOfPunts`, `totalPuntingYards`, `averagePuntYardage`, `longestPuntYard`, `puntsInside20`

### `returnStat`

`numberOfGames`, `puntReturns`, `muffedPunts`, `touchdownReturns`, `puntReturnYards`, `longestPuntReturn`, `positiveReturnRate`

## Special teams

```http
GET /v1/blitz-api/schedules/{scheduleId}/player-statistics?categories=puntStat&categories=returnStat
```

Response still includes all five keys; QB / offense / defense are `[]`.

## Optional `teamId` filter

```http
GET /v1/blitz-api/schedules/{scheduleId}/player-statistics?teamId=6917707a0e8f6ee5171235c2
```

- Omit `teamId` → both teams (when both have plays)
- Provide home `teamOneId` or linked away `teamTwoId` → that team only
- A `teamId` that is **not** on this schedule → `400` (`teamId must be teamOneId or teamTwoId on this schedule`)

Guest opponents with only `teamTwoName` (no `teamTwoId`) do not get a separate away bucket.

## Categories query

```http
GET /v1/blitz-api/schedules/{scheduleId}/player-statistics?categories=quarterbackStat&categories=returnStat
```

Allowed values: `quarterbackStat`, `offensiveStat`, `defensiveStat`, `puntStat`, `returnStat`.

Optional: `searchTerm` (matches `player.name` or `player.jerseyNumber`).
